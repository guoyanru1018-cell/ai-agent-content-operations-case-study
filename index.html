01 / CASE OVERVIEW
01 · CHALLENGE / BEFORE

当内容生产成为每日运营任务，
重复性人工生产开始成为效率与规模化的瓶颈

问题不在“不会做”，而在每一期都要重新做一遍。
整理榜单数据→ 前后榜单对比→ 筛选重点作品→ 补充相关信息→ 趋势分析→ 撰写→ 推文编辑器手工排版→ 发布
01 / EFFICIENCY

重复工作多

每期都需要重新完成数据整理、作品解读、内容撰写与排版。

02 / EXPERIENCE

判断高度依赖个人经验

哪些作品值得重点分析、榜单变化如何解释，缺少稳定复用规则。

03 / CONSISTENCY

输出标准不统一

不同文章在结构、表格、字号、配色和产品文案等方面容易出现差异。

随着栏目进入稳定生产阶段，真正需要优化的不是“写得更快”， 而是把重复判断和执行步骤沉淀成一套可复用的生产机制。

01 / DATA RULES

Data Rules

数据判断规则

统一榜单中的排名、热度、新增播放、题材、内容形态等字段定义，并建立前后期数据对比口径。

排名变化新增播放热度内容形态
02 / PRIORITY RULES

Priority Rules

重点作品筛选

用明确规则判断哪些作品值得进入深度分析，而不是每期依赖人工主观选择。

新上榜黑马剧排名明显上升连续霸榜热门 IP 续作新内容形态
03 / ANALYSIS FRAMEWORK

Analysis Framework

趋势分析框架

要求 Agent 从内容形态、题材、人物关系、开场钩子、IP 复用、多语种发行和平台变化等维度，提炼 2–3 个真正值得关注的变化，而不是简单复述榜单。

内容形态题材人物关系IP 复用平台变化
04 / OUTPUT RULES

Output Rules

输出规范

固定文章结构、表格字段、字号、紫色视觉体系、产品文案，以及 HTML / Markdown 输出格式。

固定结构表格字段紫色体系HTMLMarkdown

这个项目最终沉淀的，
不是一条 Prompt，而是一套生产机制

01

Workflow Design

把原本人工 SOP 拆解为可以被 Agent 执行的阶段。

02

Prompt Engineering

设计固定角色、任务目标、分析维度、输出结构和质量检查 Prompt。

03

Rule System

建立数据字段、重点作品筛选与趋势分析规则。

04

Structured Output

统一 HTML、Markdown、表格、字号、配色和 CTA。

05

Iteration

结合真实输出和内容表现持续调整 Prompt 与生产流程。

AI 的价值并不是替我完成一次内容创作，

持续优化的生产机制。
